# Схема LLM-вики: подготовка к экзамену «История и философия науки»

Этот файл — **схема** (конфигурация) для LLM-агента, работающего с данной вики.
Он описывает структуру, конвенции и рабочие процедуры. Агент обязан следовать
этому файлу в каждой сессии. Схема со временем со-эволюционирует: если мы
договариваемся о новом правиле — оно фиксируется здесь.

Построено по гайду Андрея Карпаты «LLM Wiki»
(https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f).

---

## Назначение

Вики — это персональная база знаний для подготовки к кандидатскому экзамену
**«История и философия науки»**.

- **Отрасль (часть II экзамена):** философские проблемы **социально-гуманитарных наук**.
- **Язык вики:** русский. Все страницы, ссылки, лог — на русском.
- **Итоговый продукт:** развёрнутые ответы на экзаменационные билеты
  (папка `wiki/билеты/`), опирающиеся на накопленный материал вики.

Пользователь отвечает за источники, направление разбора и вопросы (query).
LLM делает всю рутину: конспектирование, кросс-ссылки, раскладку по страницам,
поддержание согласованности, ведение индекса и лога.

---

## Три слоя

1. **Сырьё — `raw/`.** Курируемая пользователем коллекция источников (учебники,
   статьи, главы, конспекты лекций, программы экзамена, первоисточники).
   **Неизменяемо.** LLM читает, но никогда не редактирует эти файлы.

2. **Вики — `wiki/`.** Каталог markdown-файлов, которые целиком создаёт и
   поддерживает LLM. Конспекты источников, страницы персоналий и концепций,
   разборы, обзор, билеты. Пользователь читает; LLM пишет.

3. **Схема — этот файл (`CLAUDE.md`).** Правила игры.

---

## Структура каталогов

```
Philosophy/
├── CLAUDE.md              # эта схема
├── raw/                   # источники (курирует пользователь, LLM не трогает)
│   ├── README.md
│   └── assets/            # изображения и вложения
└── wiki/                  # база знаний (владеет LLM)
    ├── index.md           # каталог всех страниц с однострочными аннотациями
    ├── log.md             # хронологический журнал операций (append-only)
    ├── overview.md        # карта программы экзамена + общий синтез
    ├── conventions.md     # договорённости по стилю и оформлению
    ├── источники/         # конспект на каждый источник из raw/
    ├── персоналии/        # мыслители, школы, направления
    ├── концепции/         # идеи, методы, проблемы, «-измы»
    ├── разборы/           # сравнения и синтезы нескольких источников/страниц
    └── билеты/            # развёрнутые ответы; папка на раздел: билет-1/, билет-2/
```

Соответствие терминам гайда: `источники` = sources, `персоналии` = entities,
`концепции` = concepts, `разборы` = analyses.

## Именование файлов

- Латиница не обязательна: имена файлов — **строчными по-русски, через дефис**.
  Obsidian корректно работает с кириллицей в именах и в `[[вики-ссылках]]`.
- Персоналии: `фамилия-имя.md` — напр. `персоналии/поппер-карл.md`,
  `персоналии/венский-кружок.md`.
- Концепции: короткое понятие — `концепции/фальсификационизм.md`,
  `концепции/объяснение-и-понимание.md`.
- Источники: `источники/<краткий-слаг>.md` — напр.
  `источники/степин-философия-науки-2006.md`.
- Билеты: одна папка на раздел экзамена —
  `билеты/билет-1/` (Раздел I «Общие проблемы философии науки») и
  `билеты/билет-2/` (Раздел II «Философские проблемы социально-гуманитарных наук»).
  Внутри — по файлу на каждый вопрос: `NN-<краткая-тема>.md`, где `NN` — номер
  вопроса в разделе по официальному перечню ([[вопросы-экзамена-сгн]]), с ведущим
  нулём (`01` … `25`). Напр. `билеты/билет-1/04-стадии-эволюции-науки.md`.
  Если номер неизвестен — `билеты/билет-1/<краткая-тема>.md`.
- Разборы: `разборы/<что-с-чем>.md` — напр.
  `разборы/поппер-vs-кун.md`.

Кросс-ссылки — в стиле Obsidian: `[[фальсификационизм]]`, `[[поппер-карл]]`.
Ссылаться можно на ещё не созданную страницу — это помечает пробел, который
стоит заполнить позже.

## Frontmatter (YAML) — обязателен на каждой странице

```yaml
---
title: Фальсификационизм
type: концепция          # источник | персоналия | концепция | разбор | билет | обзор
tags: [философия-науки, демаркация, поппер]
status: стаб             # стаб | черновик | готово
created: 2026-09-07
updated: 2026-09-07
sources: []               # слаги страниц из wiki/источники/, на которых основан текст
раздел: I                 # I (общие проблемы) | II (социально-гуманитарные науки) | оба
билеты: []                # номера билетов, где тема задействована (если известно)
---
```

Правило `status`:
- **стаб** — только каркас, содержания почти нет;
- **черновик** — есть содержание, но не выверено по источникам / неполно;
- **готово** — выверено минимум по одному источнику из `sources`, кросс-ссылки на месте.

## Форматы страниц

### Персоналия
```
## Кто это, годы жизни, контекст
## Главный вклад в философию/историю науки
## Ключевые работы
## Оппоненты и полемика
## Термины, введённые в оборот
## Связи        — маркированный список [[вики-ссылок]]
## Что могут спросить на экзамене
```

### Концепция
```
## Суть в двух-трёх фразах
## Ключевые положения
## Кто предложил / развивал        — [[персоналии]]
## Контекст: что критиковали, что пришло на смену
## Критика и трудности
## Значение для социально-гуманитарных наук   (если релевантно разделу II)
## Связи
## Что могут спросить на экзамене
```

### Конспект источника
```
## Выходные данные        — автор, название, год, что за источник
## О чём источник в целом
## Тезисы по главам / разделам
## Ключевые определения и формулировки (близко к тексту, с указанием страниц)
## Куда это раскладывается по вики   — список затронутых [[страниц]]
## Цитаты для билетов      — дословно, со страницами
```

### Разбор
```
## Вопрос / что сравниваем
## Позиции сторон
## Таблица сопоставления (если уместно)
## Вывод / синтез
## Открытые вопросы
## Связи
```

### Билет
```
## Формулировка билета
## План ответа (тезисно, 5–9 пунктов) — то, что проговариваем на экзамене
## Развёрнутый ответ
   - по каждому пункту плана: суть, персоналии с датами, определения,
     ключевые работы, полемика
## Определения под запись        — 4–8 терминов строгими формулировками
## Персоналии и даты             — компактный список
## Возможные дополнительные вопросы и краткие ответы
## Источники и литература         — [[источники]] + внешние ссылки
## Связи                         — [[концепции]], [[персоналии]], смежные [[билеты]]
```

## Рабочие процедуры

### Ingest (загрузка источника)
Пользователь кладёт файл в `raw/` и просит обработать. Порядок:
1. Прочитать источник целиком.
2. Кратко проговорить с пользователем ключевые тезисы, уточнить акценты.
3. Создать `wiki/источники/<слаг>.md` по формату конспекта.
4. Разложить материал: создать/обновить страницы в `персоналии/` и `концепции/`
   (типично затрагивается 5–15 страниц). Проставить кросс-ссылки в обе стороны.
   Обновить `status` затронутых страниц, если содержание выросло.
5. Обновить `wiki/index.md`.
6. Дописать запись в `wiki/log.md`.
7. Коротко отчитаться: какой конспект создан, какие страницы затронуты.

По умолчанию — по одному источнику за раз, с участием пользователя.

### Query → билет (основной сценарий)
Пользователь присылает формулировку билета (query). Порядок:
1. Прочитать `wiki/index.md` и `wiki/overview.md`, найти релевантные страницы.
2. Прочитать эти страницы (`концепции/`, `персоналии/`, `источники/`).
3. Если критичных страниц не хватает — сказать об этом и предложить, какие
   источники загрузить; при согласии пользователя создать недостающие
   страницы-концепции из имеющихся знаний, пометив `status: черновик`.
4. Написать `wiki/билеты/билет-<1|2>/NN-<тема>.md` (папка — по разделу экзамена,
   `NN` — номер вопроса в разделе) по формату билета, с цитатами и ссылками на
   `[[источники]]`.
5. Обновить `index.md` и `log.md`. Проставить номер билета в `билеты:` во
   frontmatter задействованных концепций/персоналий.
6. Выдать пользователю полный текст ответа в чат.

Ответы не растворяются в истории чата — всё ценное оседает в `wiki/`.

### Lint (ревизия вики)
По запросу пользователя — проверка здоровья вики:
- противоречия между страницами;
- устаревшие утверждения, перекрытые более новыми источниками;
- страницы-сироты без входящих ссылок;
- важные понятия, упомянутые, но без своей страницы;
- недостающие кросс-ссылки;
- пробелы, которые стоит закрыть загрузкой источника или веб-поиском;
- страницы в статусе `стаб`/`черновик`, до которых давно не доходили руки.
Выдать список проблем и предложить, что делать. Правки — только с согласия
пользователя.

## index.md и log.md

**index.md** — содержательный каталог. Каждая страница вики: ссылка `[[...]]`,
одна строка аннотации, метка `status`, число источников. Сгруппировано по
разделам (персоналии / концепции / источники / разборы / билеты). LLM обновляет
на каждом ingest и на каждом билете.

**log.md** — хронологический журнал, только добавление в конец. Каждая запись
начинается с единого префикса:

```
## [2026-09-07] ingest | Название источника
## [2026-09-07] билет | Билет 03. Научные революции и типы рациональности
## [2026-09-07] lint | Ревизия: 4 сироты, 2 противоречия
```

Так лог парсится простыми средствами: `grep "^## \[" wiki/log.md | tail -5`.

## Договорённости по содержанию

- Держать вместе **историю** и **философию**: у каждой концепции — исторический
  контекст (кто, когда, в ответ на что), не только логическая суть.
- Русскоязычная традиция обязательна к учёту: типология научной рациональности
  **В. С. Стёпина** (классическая / неклассическая / постнеклассическая),
  структура и основания научного знания в его изложении — это каркас многих
  билетов части I.
- Для части II всегда явно проговаривать специфику социально-гуманитарного
  познания: совпадение субъекта и объекта, ценностная нагруженность,
  «понимание» vs «объяснение», роль языка и текста.
- Даты и годы жизни персоналий — обязательны. Названия ключевых работ — с годом
  первого издания.
- Цитаты — дословно, с указанием источника и страницы, в блоке цитат конспекта.
- Не выдумывать библиографию. Если источник не загружен в `raw/` — помечать
  утверждение как требующее проверки.

Стиль оформления и прочие мелочи — в `wiki/conventions.md`.
